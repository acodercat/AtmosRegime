# E7：参考手册对照（不训练，只给知识）

## 目的

已有发现：8B 和更大的模型在 regime 陷阱上失败，主要是**想不起替代方法**——告诉它"标准方法在这里不适用"（flag 臂）几乎没用，
直接写出替代公式（given 臂）就能做对。E7 检验：如果不训练，只在题前放一本**大部分与本题无关**的参考手册，
让模型自己判断哪一条适用，能否得到 given 臂的大部分收益。它是 RL 训练的对照：训练要证明自己比"把知识塞进提示"更有价值。

**这是一份量身定做的手册，测的是上限**：60 条每条都对应至少一个被测模板或陷阱，所以"正确的那条一定在手册里"。
结果只能说明"知识齐全、只需挑对条目"时能修好多少，不能说成"给一本普通参考书就行"。通用手册（含与被测机制无关的条目）
是另一个实验，视本实验结果再定。

## 手册内容

- `explore/handbook.md`：60 条，每条三行同一格式——`### <标准关系>` / `Valid when: <适用条件，能量化的给出量化>` /
  `Outside that: <替代关系或修正，带公式>`，并在括号里注明通常的教科书出处。
- 按主题排序（动力、热力、云物理、辐射与气候、化学、气溶胶、边界层、空气质量、观测、水文），**不按是否为陷阱分组，
  也不标注哪条相关**。条目只写通用教科书知识：不含任何具体题目的数值、模板名或陷阱 id，不写"本题"。
- 覆盖：53 个模板（原 30 + 扩展 23）的机制，加上测试侧 40 道 `regime:recognise` 教科书陷阱（母题不在 train 划分；
  其中 2 道带 `magnitude_defect`）的机制。同一物理机制合并为一条（例如冰面饱和 = `ice_saturation` + 三道教科书陷阱）。
  每条覆盖哪些模板 / 陷阱记在 `explore/handbook_map.json`，**只用于分析，从不给模型看**；全部模板和陷阱均已映射，没有无法映射的。
- 长度约 22.9k 字符，按 字符数/4 估约 5.7k token（含较多 Unicode 符号，实际 tokenizer 计数会更高，运行前用目标模型的
  tokenizer 实测）。
- **独立复核（2026-10-03）通过并已改正**：60 条物理逐条核对；按手册公式独立实现后，53/53 个模板（每模板 40 组越界题，
  最大偏差 mie_geometric 3.1%、clausius_clapeyron 2.9%）和 40/40 道陷阱（最大 0.8%）都在 5% 判分容差内复现答案。
  改正 6 处：雨滴第三段系数 2.2×10³ → 2.01×10³（与 Rogers & Yau 及 `drop_ventilation` 一致）；Haldane 出处；
  垂直路径 Δp 写成对数平均压强的精确式；球面涡度出处；两层温室模型改为 N 层通式（原句正好是某道陷阱的构型）；谱线线型出处。
  另有几条带轻微针对性的表述（惯性圆、摩擦突变后的振荡、旋转水槽中 f = 2Ω 等），都是通用物理、不含题目数值，保留。

## 输入如何构建

```
uv run python -m explore.build_handbook_input --in <已有输入>.json --out <输出>.json
```

逐行复制，只改两处：`id` 加前缀 `hb:`（不会与原行冲突，也不会从原行的结果续跑）；`problem` 变为
`手册全文 + 空行 + "---" + "Use the reference notes above only where they apply." + 空行 + 原题`。其余字段（答案、
`variant`、`template`、`parent_id` 等）原样保留，所以已有的报告脚本可以按原字段分组。手册对每一行完全相同。

## 用在哪些已有输入上

1. **模板**：inside / outside / given 三臂的模板题，例如 `experiments/_inputs/e0_confirm.json`（17 个模板，新种子 20261002，
   1360 行）。**手册只加在 inside / outside 行上**，`flag:` 与 given 行不加（两种帮助叠加就分不清各自的作用）；
   given 臂直接用已有运行。
2. **教科书陷阱 + 母题**：`uv run python -m explore.build_e1_input --families --out <path>.json`（所有 held-out、sound
   的陷阱及其母题，当前 199 + 199 行），再经 `build_handbook_input`；主分析取其中的 `regime:recognise` 子集，其他家族
   作为"手册对非 regime 题有无影响"的旁证。教科书陷阱的 given 臂用 `explore.build_given_input` 已有的替代给出版本。

## 对照臂

| 臂 | 题面 | 来源 |
|---|---|---|
| none | 原题 | 已有运行，或与 handbook 臂同服务器、同种子重跑 |
| handbook | 手册 + 原题 | 本文件的输入 |
| given | 原题 + 一句写出替代公式 | 模板的 given 变体；教科书陷阱的 given 版本 |

主要比较：在 outside 和 trap 上，handbook 臂恢复了 none→given 差距的多少；在 inside 和 parent 上，handbook 臂相对 none
是否下降。判据与样本量由负责人在运行前写定，本文件不预设。

## 风险

- **长度与 8B 的上下文利用**：约 6k+ token 的前缀可能稀释注意力，或让 8B 模型套用不相关的条目；失败可能来自
  "找不到/选错条目"而不是"不会用"。分析时应区分（例如看解答是否引用了正确条目对应的公式）。
- **手册也出现在 inside 与 parent 行上**：模型可能在标准方法本来正确时也去套用修正（例如对短程雷达也用 4/3 地球半径、
  对小幅变化也用对数强迫——后者数值上无害，但对其他条目未必），从而伤害标准题。这必须测，不能假设为零。
- **手册与 given 臂不完全等价**：given 臂给出的是带本题常数的那一句；手册给的是通用形式，有些常数（如某种酸的 K_a、
  具体的 N₂O 背景浓度）手册不提供。handbook 低于 given 不一定全是"选择条目"的代价。
- **条目覆盖了所有被测机制**：手册的每一条都对应至少一个模板或陷阱，没有纯干扰条目；对任一道题来说其余 59 条是无关的，
  但"手册里一定有答案"这一点本身是一个提示，与真实场景不同。
