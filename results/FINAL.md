# Final results — Qwen3-8B, DAPO, step 120

Every number below is regenerated by `atmoscoder_rl.analysis` from the stored Bench-harness
runs; nothing is transcribed. Verdicts are re-derived from each record's `details` with
units. Base is the majority of three repetitions; each RL column is one run of the frozen
configuration under a different seed.

```
uv run python -m atmoscoder_rl.analysis paper      # table 1
uv run python -m atmoscoder_rl.analysis control    # table 2
uv run python -m atmoscoder_rl.analysis pairs --control   # table 3
```

**Two denominators here move when the corpus does**, so re-run all three after any re-vendor:
the clean-expansion probe is derived from `traps.json` at runtime (93 → 130 → 135 as traps
were added), and the trap arms come from `traps.arm_ids`. The fixed splits (`test_id` 64,
`test_core_only` 63, `test_book` 56, `probe_trap` 67, scaffolding 77, cross-domain 131) do
not move; a change in one of those is a bug, not new data.

## 2. It is not a spurious-reward effect

Same configuration, same step, reward replaced by a coin flip:

| probe | real | random |
|---|--:|--:|
| test_id | +28.1 | −3.1 |
| test_book | +21.4 | −1.8 |
| traps, expansion clean | +21.5 | −3.0 |
| scaffolding stripped | +24.7 | −3.9 |
| **cross-domain** | **+21.4** | **−2.3** |

All nine probes fall between −3.9 and +3.0 (the table shows five; `python -m atmoscoder_rl.analysis control` prints all nine). [Spurious Rewards](https://arxiv.org/abs/2506.10947)
does not reproduce on execution-verified environmental computation, and the
[mechanism paper](https://arxiv.org/abs/2601.11061) explains why: it needs memorised
answers to activate, and numeric variants recompute theirs.

## 3. Where it fails — paired trap vs parent

A trap and its untouched parent are one problem under two conditions, so the test is
McNemar on the discordant pairs. Arms are separated by upstream's adjudication.

| arm | pairs | base | four RL runs | p | reading |
|---|--:|---|---|--:|---|
| **regime: must recognise the failure** | 46 | 10 : 3 (p=0.09) | **65 : 11** | **<10⁻⁷** | the parent runs away |
| regime: replacement handed over | 21 | 5 : 4 (p=1.00) | 15 : 11 | 0.56 | no gap |
| geometry: same method, extra step | 72 | 9 : 3 (p=0.15) | 31 : 35 | 0.71 | no gap |

All four runs are individually significant on the regime arm (p = 0.0001, 0.0127, 0.0072,
0.0026). Contrasts: regime vs replacement-given **χ²(1) = 8.9**; regime vs geometry
**χ²(1) = 24.0**; the two controls against each other χ²(1) = 0.9.

The random-reward arm moves the same way (7 : 0, p = 0.016) but for a different reason: it
drives the traps from 8.7% down to 2.2% *and* the parents from 23.9% to 17.4%. Both sides
degrade, the traps further. Real reward lifts the parents to 45–48% and the traps to 11–17%.
A paired test alone cannot tell those apart, so the accuracies belong beside it.

**The deficit is the recognition step, not the physics and not the perturbation.** Traps
whose text hands over the replacement relation are solved 52–67% of the time after RL and
show no gap at all; the same family, same construction, with the recognition step left in,
is solved 11–17% and falls 6:1 behind its own parents.

Supporting, reported apart: 14 cross-domain regime traps give 16 : 1 (p = 0.0003), but 11 of
their 14 parents are soil and those parents are easier than the cross-domain set as a whole,
so this shows the effect exists outside atmospheric science without attributing it to
training.

## 3b. It is the policy gradient, not the data

Two supervised controls on the same 1140 rows, same model, same prompt
(`sft/gold_sft.md`, `sft/raft.md`):

| arm | supervision | train split | held-out probes |
|---|---|--:|---|
| SFT gold | human-written certified solvers | **91.6** | nothing moves |
| RAFT | the model's own verified rollouts | 54.7 | nothing moves |
| **RL s120** | the same rollouts, reinforced | 82.1 | **+21 to +28** |

RAFT is the clean comparison — it changes only the algorithm — and it does not transfer
either, so the gold arm's failure was not about the supervision being pipeline-authored.
On the regime arm every non-RL arm leaves the traps at 2.2%, the random-reward arm included;
only RL raises them (13.0%) and only RL moves the parents (+24). RL also reaches a *lower*
training accuracy than gold SFT while generalising far better.

## 4. Why — the training distribution

| | n | regime problems |
|---|--:|---|
| training split | 190 | **3–6 (1.6–3.2%)** |
| held-out core | 183 | 5–10 (2.7–5.5%) |
| whole census | 567 | 16–25 (2.8–4.4%) |

Each training parent contributes itself plus five numeric variants, so regime problems are
**18–36 of 1140 training rows**. Independently, base pass@64 on a regime trap averages 0.2
correct samples in 64. RL cannot amplify what the base almost never produces and the
training set almost never contains.

Regime problems are also **not spread evenly**: close to one in five in hydrology, one in
fifty in atmospheric science, none at all in ecology or environmental chemistry.

## 5. RL does not narrow the model's reach

pass@64 over 444 paired held-out problems: coverage **64.9% → 75.5%**, 19 problems lost (all
with base k ≤ 8), 66 gained. No [pass@k inversion](https://arxiv.org/abs/2607.20543). Gains
concentrate in the band where the base already samples a correct method sometimes (k = 1–47)
and leave the already-reliable problems untouched.

*Caveat: base k is collinear with problem length (median 498 characters in the k = 0 bin,
263 in the k = 64 bin), so the band analysis cannot separate sampling probability from
difficulty. Every split shows the coverage gain separately, so the conclusion does not rest
on the binning.*
